## 设计依据

已检查当前 Compose 主题、五标签导航、通知列表、规则截图，以及场景、计划和我的页面代码。仓库截图用于视觉参考，当前功能结构以代码为准。概念图中的通知、规则名称和数字均为演示数据，不是设备真实数据。

提案时的界面以 Material 3 实色卡片为主。优化重点不是增加功能，而是明确状态、内容和操作的主次，让高频通知阅读更轻松。

## 三个方向

| 方案 | 图片 | 视觉特征 | 取舍 |
| --- | --- | --- | --- |
| A 冰川白 | a-glacier.png | 蓝白磨砂、墨蓝正文、克制的蓝色强调 | 优先推荐，兼顾玻璃质感和长时间阅读 |
| B 暖玉绿 | b-jade.png | 暖白、浅玉绿背景、深绿强调 | 更柔和、有辨识度，避免大面积绿色影响状态色识别 |
| C 深海蓝 | c-midnight.png | 深蓝烟熏玻璃、青蓝强调、浅色正文 | 暗色方向，注意弱光下次级文字的对比度 |

每套展示通知和规则两页，以相近内容比较视觉方向。生成图用于确认整体气质，文字、图标和局部间距不是最终验收规格。

## 共同改进

- 保留通知、规则、场景、计划、我的五个入口，不改变已有业务闭环。
- 状态卡压缩为采集状态、开关和简洁计数；正常状态不反复解释权限与连接，异常状态必须明确显示原因和恢复入口。
- 搜索、分组与应用筛选保持可见。测试通知、日志、清空等低频操作收进更多菜单；清空仍需确认。
- 规则卡展示名称、适用范围、简短条件和动作标签；点击卡片进入编辑，开关独立操作。
- 场景沿用相同卡片组件，以时间、网络等图标配短标签表达条件；计划突出时间和重复周期。
- 我的页面改为分组设置列表，复杂备份、转发配置按需展开，不在首页堆满表单。
- 通知详情以清晰阅读和复制为核心，技术字段收进次级信息区，不删除排障能力。

## 落地边界

- 毛玻璃优先用于状态区、底部导航和浮层；消息正文使用更高不透明度，避免背景干扰。
- 使用应用内柔和背景提供透色，不要求读取系统壁纸，也不把整个 Activity 做成透明窗口。
- 先建立共用颜色、圆角、间距和玻璃容器，再覆盖各页，避免每个页面单独堆叠效果。
- 项目最低支持 Android 8（API 26）。真实背景模糊的版本兼容与滚动开销需要验证；旧系统保留半透明色、细边框和静态柔光背景作为降级。
- 不能直接模糊承载正文的整个组件；玻璃背景与前景文字应分层处理。长列表避免逐卡高成本实时模糊。
- 保留大字体、触控区域、手势栏安全区与列表底部留白；浮动导航不可遮挡最后一条记录。
- 若选择固定品牌色，需要明确当前 Android 动态取色的策略，避免系统壁纸颜色破坏选定风格。

## 当时的验收计划

先实现通知页和共用导航，再扩展其余页面；通过截图、交互验证和针对性回归测试检查未授权、连接、暂停、空数据、长文本及大字体状态。实际完成范围与仍待真机确认的项目，见 [后续验收报告](../acceptance/ACCEPTANCE.md)。

# PickMsg 设计规范 · 暖玉绿 v1

[文档导航](../README.md) · [构建与开发](../development.md) · [界面验收](acceptance/ACCEPTANCE.md)

更新：2026-10-29。适用范围：Android 应用的通知、规则、场景、计划、我的，以及编辑、详情和常驻通知管理页。

这是项目后续界面开发的统一约定。设计图只提供方向；尺寸、组件行为以本文和 `ui/theme/` 为准。修改规范时，必须同步修改代码中的设计常量，不再逐页设置相似但不同的值。

## 1. 设计原则

1. 阅读优先：背景有层次，正文不模糊；装饰不能抢过通知内容。
2. 克制的玻璃感：暖白、玉绿、薄边框，不使用大面积高光、霓虹或每卡阴影。
3. 一致但不机械：内容卡片、输入控件、导航、弹窗分级处理，不把所有东西做成同一种大圆角。
4. 操作可识别：图标优先，导航保留短标签；图标按钮必须有无障碍名称。非直观操作不能只靠图标猜测。
5. 不增加业务：视觉统一不顺带改变授权、采集、规则命中、转发和底层数据删除语义；交互防护调整需明确记录并验证。

## 2. 规范与代码入口

| 职责 | 文件 / API |
| --- | --- |
| 颜色、深浅主题 | `app/src/main/java/com/pickmsg/app/ui/theme/Theme.kt` |
| 间距、圆角、尺寸、阴影、透明度、文字 | `app/src/main/java/com/pickmsg/app/ui/theme/DesignTokens.kt` |
| 页框、标题栏、卡片、按钮、筛选项、标签 | `app/src/main/java/com/pickmsg/app/ui/theme/Components.kt` |
| 背景与半透明材质 | `app/src/main/java/com/pickmsg/app/ui/theme/JadeGlass.kt` |

页面只引用 `MaterialTheme` 和 `PickMsg*` 常量/组件。不要在页面里新增十六进制颜色、`RoundedCornerShape(…)`、自定义阴影或随意的间距数字。图表刻度、业务输入框宽度等内容相关尺寸可以在局部定义，不要求把所有数字都变成全局常量。

## 3. 颜色与状态

| 角色 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 主色 primary | `#28684F` | `#A3D4B6` | 主按钮、选中、启用 |
| 背景 background | `#F6F3EA` | `#131D18` | 页面基底 |
| 表面 surface | `#FCFAF4` | `#1C2821` | 卡片和控件基底 |
| 正文 onSurface | `#20372D` | `#E2E9DF` | 标题、正文 |
| 次级文字 onSurfaceVariant | `#58665C` | `#B9C5B8` | 时间、摘要、辅助标签 |
| 提醒 tertiary | `#88602A` | `#E2BF87` | 暂停、等待、非致命提示 |
| 错误 error | Material 错误语义色 | Material 错误语义色 | 错误、危险操作 |

- 使用语义颜色，不以某个固定绿色代替所有状态。
- 正常、暂停、等待、错误必须同时有短文本，不仅靠红绿区分。
- `outline` 用于边界和装饰，不用作大段辅助正文颜色。
- 深浅模式跟随系统；品牌配色固定，不跟随壁纸动态取色。
- 禁用状态沿用 Material 的语义与透明度，不通过消失或单独变灰的文字模拟。

## 4. 圆角

| 组件 | 圆角 | 常量 |
| --- | --- | --- |
| 只读状态标签 | 8 dp | `PickMsgShape.badge` |
| 输入框、普通按钮 | 12 dp | `PickMsgShape.control` |
| 应用标识底板 | 12 dp | `PickMsgShape.icon` |
| 内容卡片、创建浮动按钮 | 20 dp | `PickMsgShape.card` |
| 底部导航容器 | 24 dp | `PickMsgShape.dock` |
| 对话框 | 28 dp | `PickMsgShape.dialog` |
| 搜索框、筛选项、圆形状态底板 | 50% | `PickMsgShape.pill` |

搜索是胶囊，编辑表单不是胶囊。只读标签与可点击筛选项必须视觉区分。嵌套组件的圆角应小于外层卡片，避免大圆角层层套娃。

`MaterialTheme.shapes` 同时映射 8 / 12 / 16 / 20 / 28 dp，供对话框等 Material 原生组件使用；按钮、输入框、卡片、导航使用明确的语义形状。

## 5. 间距与布局

基于 4 dp 的节奏；2 dp 只用于紧凑标签内边距和紧邻文字。统一使用 dp，字体使用 sp。

| 场景 | 值 | 常量 |
| --- | --- | --- |
| 页面左右边距 | 16 dp | `PickMsgSpace.page` |
| 内容卡片内边距 | 16 dp | `PickMsgSpace.card` |
| 列表卡片间距 | 12 dp | `PickMsgSpace.listGap` |
| 表单项间距 | 12 dp | `PickMsgSpace.fieldGap` |
| 独立内容区块间距 | 24 dp | `PickMsgSpace.sectionGap` |
| 图标与正文间距 | 12 dp | `PickMsgSpace.md` |
| 并列按钮、筛选项间距 | 8 dp | `PickMsgSpace.sm` |
| 标题与摘要间距 | 4 dp | `PickMsgSpace.xs` |
| 页面顶部 / 底部留白 | 8 / 24 dp | `PickMsgSpace.pagePadding` |
| 有浮动按钮的列表底部 | 96 dp | `PickMsgSpace.listWithFabPadding` |
| 导航左右 / 上下外边距 | 12 / 8 dp | `dockHorizontal` / `dockVertical` |

- 普通列表用 `pagePadding`；带创建浮动按钮的列表用 `listWithFabPadding`。
- 管理卡片采用 16 dp 内边距，整卡点击进入编辑，不再增加重复的编辑行；开关独立操作。
- 页面安全区由 Scaffold 与导航容器统一处理，子页面消费已分配的 Insets，不能重复手动补状态栏高度。
- 宽度不足的筛选项横向滚动；表单多选项和并列操作使用可换行布局，禁止挤压到文字不可读。
- 不固定卡片高度；大字体和多行内容必须能撑高容器。窄屏优先单列，不为了“仪表盘感”强行双列。

## 6. 材质、边框与阴影

| 层级 | 材质 | 阴影 |
| --- | --- | --- |
| 页面背景 | 暖色基底 + 静态玉绿/暖色柔光 | 0 dp |
| 正文卡片 | surface 88% 不透明度 + 1 dp 渐变边框 | 0 dp |
| 状态卡 | surface 65% 不透明度 + 1 dp 渐变边框 | 0 dp |
| 底部导航 | surface 65% 不透明度 + 1 dp 渐变边框 | 0 dp（避免半透明表面透出阴影底板） |
| 创建浮动按钮 | Material 主色容器 | 默认/按下/聚焦 6 dp，悬停 8 dp |
| 对话框、菜单 | Material 实色浮层 | 沿用 Material 浮层处理，不自行叠加多重阴影 |

阴影只表达浮起层级，不作为每张卡片的装饰。卡片通过边框和透色区分即可。深色模式靠边框、表面色差分层，不额外增强黑色阴影。

当前玻璃是**静态柔光背景 + 半透明材质**，不是真实背景模糊。兼容 API 26，避免长列表逐项采样背景。若未来引入实时模糊，需单独评估滚动性能、耗电、兼容与降级，不允许模糊正文。

## 7. 文字层级

| 语义 | 字号 / 行高 | 字重 | 使用场景 |
| --- | --- | --- | --- |
| headlineSmall | 28 / 36 sp | 600 | 状态统计数值 |
| titleLarge | 22 / 30 sp | 600 | 页面标题 |
| titleMedium | 16 / 24 sp | 600 | 区块标题、主要状态 |
| titleSmall | 14 / 20 sp | 600 | 卡片标题 |
| bodyLarge | 16 / 24 sp | 常规 | 详情正文、输入内容 |
| bodyMedium | 14 / 22 sp | 常规 | 列表正文 |
| bodySmall | 12 / 18 sp | 常规 | 摘要、辅助说明 |
| labelLarge | 14 / 20 sp | 500 | 操作按钮、筛选项 |
| labelMedium | 12 / 18 sp | 500 | 应用名称、导航标签 |
| labelSmall | 11 / 16 sp | 500 | 时间、紧凑只读标签 |

使用系统字体及中文回退，不额外下载字体；遵循系统字体缩放。日志可使用等宽字体，其余业务界面不使用等宽排版。

列表标题最多 1 行、正文通常 2 行，截断时可以进入详情阅读完整内容。规则摘要允许 2 行、场景条件允许 3 行。详情与错误说明不应为了整齐而丢失关键内容。

## 8. 组件约定

| 组件 | 使用方式 |
| --- | --- |
| 页面 | `PickMsgScaffold`，统一透明页面底与安全区行为；根导航保留独立 Scaffold |
| 顶栏 | `PickMsgTopBar`，统一背景材质和标题样式，保存/返回等回调仍由业务页提供 |
| 卡片 | `PickMsgCard`；内容自行使用 `PickMsgSpace.card`，不依赖隐式重复内边距 |
| 可点击通知卡 | `JadeGlass(onClick = …)`，保留水波纹与可点击语义 |
| 主操作 | `PickMsgButton`，12 dp 圆角，最小高度 48 dp；同一区域避免多个同权重主按钮 |
| 次操作 | `PickMsgOutlinedButton`，同样 12 dp / 48 dp |
| 文字操作 | Material `TextButton`，用于编辑、取消等低强调操作，不额外加底板 |
| 创建入口 | `PickMsgFloatingActionButton`，规则、场景、计划保持现有创建流程 |
| 筛选项 | `PickMsgFilterChip`，统一胶囊形状、边框和标签内边距；主分组可设 `prominent = true` |
| 只读标签 | `PickMsgBadge`，8 dp 圆角，不模拟成可点击按钮；暂停/隐藏等可用 warning 配色 |
| 输入框 | Material `OutlinedTextField` + `PickMsgShape.control`，保留 label / supportingText / isError |
| 对话框 | Material `AlertDialog`，继承统一主题形状；确认/取消职责不得因视觉修改交换 |

图标通常 24 dp，紧凑图标 20 dp，应用标识底板 40 dp。交互触控区域至少 48 dp。装饰性图标的描述设为 null，功能性图标提供明确中文描述。

不使用固定说明大段解释正常状态；未授权、连接失败、不可用等阻断状态必须有原因和可执行入口。技术字段不是首页主信息；通知详情默认折叠诊断字段，仍保留完整阅读与复制能力。

## 9. 动效与无障碍

- 当前沿用 Material 的点击、开关、选择反馈，不引入持续背景动画、闪烁或反复弹跳。
- 后续新增过渡以短促淡入/颜色变化为主，不做逐条长延迟列表入场；应尊重系统动画设置。
- 重要状态由文字和图形共同表达；不要把透明度降到正文不可读。
- 正文目标对比度至少 4.5:1，大字和关键非文本边界至少 3:1；半透明材质需以最终背景合成后检查，不能只比较两种源颜色。
- 1.5 倍字体、小屏、深色必须进入视觉检查；2 倍字体及真机属于后续完整无障碍验收，不能仅凭默认字号截图宣布全部适配。

## 10. 适用范围与维护

已接入主题与共用页面组件：五个主页面、规则/场景/计划编辑页、通知详情、常驻通知管理。已归一化页面和卡片间距、列表节奏、输入框形状、筛选项、按钮、标签、标题栏和底部导航。

规范覆盖应用内 Compose 界面，不定义数据库、规则匹配和转发逻辑。桌面 Glance 小组件及系统通知由独立渲染体系负责，尚未按这套组件迁移。具体改动及验证结论见验收报告，不以本文代替测试结果。

新增页面检查清单：

- [ ] 引用现有主题/组件，不复制一套颜色和圆角。
- [ ] 说明新增尺寸或组件为何不能复用；不要为了一个页面扩展无意义的全局常量。
- [ ] 默认、选中、禁用、错误、空数据、长文本状态清晰。
- [ ] 深浅主题和大字体不遮挡主要操作。
- [ ] 底部最后一条内容、输入键盘与悬浮按钮互不遮挡。
- [ ] 纯视觉改动进行构建和截图检查；涉及业务逻辑时增加对应核心流程测试。

调规范的顺序：先改 `DesignTokens.kt` / `Theme.kt`，再改共用组件，最后才处理页面特例。业务代码不得覆盖规范去“补齐”局部截图。

## 11. 精修补充（2026-10-29）

- 管理列表使用 `PickMsgManagementCard`：整卡进入编辑，开关单独操作；标题最多两行、摘要最多三行。
- 删除操作使用 `PickMsgDeleteAction` 二次确认；取消与系统返回不得执行删除。
- 编辑页系统返回与页内返回一致；编辑、详情和工具等二级页面隐藏底部导航，主页面显示键盘时也隐藏导航，为操作与输入留出空间。
- 场景条件和格式化弹窗的正文可独立滚动，确认/取消留在弹窗底部。
- 设置页的备份、邮件账号按需展开；详情中的诊断字段按需展开，不删除数据。
- 计划权限提示与列表共同滚动，避免小屏/大字体下挤掉主要内容。
- 半透明导航取消平台投影，使用边框与留白分层，避免投影底板透过材质。

透明页框必须显式指定 `onBackground` 正文色，不能依赖透明容器推导前景色，以免深色模式出现黑字。
